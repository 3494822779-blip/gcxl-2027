# 机器人动作行为说明

本文件约定机器人选什么目标、如何扫障与抓取、何时停止。修改文档不会自动改变运行行为，代码和配置需要同步、构建后重启。先根据需求修改文档，经过检查git和明确改动方向后确认后再改代码；本次目标型抓取方案已确认实施。

## 一、启动与动作接口

- 普通启动等待人工任务，不自动抓取。自动运行须显式设置 `autonomous:=true target_class:=<类别>`，只执行一次目标型抓取。
- `target_grasp` 必须同时传 `has_target_class: true` 和非负的 `target_class_id`，没有默认类别。
- `approach_grasp`、`first_grasp` 是相同流程的兼容名称，也必须传类别。普通启动和 `first_grasp.launch.py` 都支持；不再限定 class_0。
- 完全停用丢弃：`discard` 和 `discard_after: true` 会被拒绝，旧 `actuator/discard` 话题也不能执行丢弃。

| 动作 | 行为 | 结束状态 |
|---|---|---|
| `target_grasp`（含两个兼容名称） | 指定类别选目标 → 锁定 → 逐个单爪扫障（有次数预算）→ 张爪、抓取 | 保持夹持、停车、相机发出回正指令 |
| `align` | 选目标并对准画面位置，不等待抓取角度，不张爪也不闭爪 | 停车 |
| `grasp` | 原地停车 → 相机到抓取角度 → 合爪并等待 | 保持夹持、停车、相机发出回正指令；不需要类别 |
| `move` | `distance_m` 正数前进、负数后退，速度为 `speed_mps` | 计时结束停车 |
| `turn` | `angle_deg` 正数左转、负数右转，速度表示每侧轮速 | 计时结束停车 |
| `claw` | 左右夹爪同时到 `angle_deg`，等待 0.5 秒 | 底盘停车 |
| `camera` | 相机到 `angle_deg`，等待新鲜有效的到位反馈 | 底盘停车 |
| `stop` | 随时中断当前动作并停车，不锁存 | 保持最后已发布的夹爪和相机目标；之后可提交新任务 |

## 二、目标选择与障碍判断

1. 在指定类别的真实检测框中，优先选下边缘最低者，再按置信度及跟踪编号打破平局。不再使用上方 class_1 排除规则。
2. 正式目标一经锁定，不因其他物块更近而更换，也不切换成障碍物。目标暂时丢失时停车等待；跟踪器改变编号时，只允许接管锁定目标丢失之前从未出现过的同类别新 ID，并要求在 `rebind_timeout` 内与原框 IoU 达到 `rebind_iou`。持续存在的障碍物 ID 会被排除，沿用已保存开度。这是几何推断，不能保证物理身份绝对相同。搜索期间暂停重绑定计时；相机停住后可用较低的 `search_rebind_iou` 做一次恢复判断。
3. 障碍须是真实检测物块，与目标横向有交集，且其下边缘比目标更低。目标上方物块不因此判为障碍。
4. 多个障碍根据物块物体距离（障碍物框的下边缘距离屏幕下边缘的距离越近的则距离车越近）近远进行扫走。
5. 扫完若还有遮挡，先恢复爪位、等待，再继续单侧扫走。默认同一障碍最多 2 次、每任务总共最多 8 次（`max_sweep_attempts` / `max_sweeps`），超出则锁存停车，不带障碍继续合爪。编号变化仍受总次数预算约束。

## 三、单侧扫走

1. 障碍相对目标中心偏左用左爪，偏右用右爪，正居中固定用左爪。选中爪内收到 **−30°**，另一爪保持当时角度；底盘先停车等待 `claw_settle_sec`，再进行扫走。
2. 内收后继续接近正式目标。横向交集宽度 / 目标宽度 **严格超过 50%** 时，叠加朝障碍反方向的转向偏置。
3. 当前 YAML 初始转向权重 **20%**，若两个框实际有面积重叠则为 **40%**；偏置为权重乘最大扫走角速度 **1 rad/s**。左障碍向右偏转，右障碍向左偏转。
4. 权重按 `w(t)=w₀·exp(−t/τ)` 衰减，当前 YAML `τ=0.23 秒`。爪内收等待结束后累计 **1 秒有效目标控制时间**，偏置归零；感知无效、目标丢失或相机反馈过期时停车并暂停计时。
5. 扫走阶段不合爪、不丢弃；提前达到抓取位置时停止前进。扫走结束后，若已保存张爪开度则恢复该开度；否则达到张爪角度后按当时正式目标宽度张爪一次。等待开爪到位时间，再检查抓取条件。
6. 单轮完成只代表扫走计时执行完，不确认障碍真的移走；固定记录本轮开始时的障碍编号。恢复爪位期间底盘停车，随后根据新观测决定继续扫障还是抓取。没有障碍落点和接触传感器确认。

## 四、普通接近与抓取

1. 水平偏差大时先转向，居中后接近；越靠近目标，视觉转向越轻。舵机模式在距抓取俯仰门槛 15° 内逐步把前进速度从 `forward_speed` 降到 `approach_min_speed`（当前 0.1 m/s）；目标中心达到画面高度 90% 时底盘停车，等待俯仰对准。比例和速度是可调策略，不能代替物理测距和制动标定。
2. 框中心位置为画面高度 **50%**，纵向归一化容差 **0.1**（即高度约 45%～55% 的目标带）。相机实际反馈低头达到当前 YAML 的 **22°**（`claw_open_pitch_deg`）且有真实目标及有效宽度时，按当时框宽计算并保存开度，只张开一次；张爪等待期间底盘停车。之后不因框宽变化、短时丢失或相机角度反复越过阈值而重新调整；扫走期间不覆盖单爪内收。
3. 目标位置合格、真实观测有效，且相机反馈新鲜、低头达到当前 YAML 的 **45°（允许低 1.7°，即 ≥43.3°）** 时允许抓取；超过抓取角度也可抓取，不设额外的抓取角度上限门槛，但反馈必须在相机配置范围及测量余量内。张爪指令等待 **0.5 秒**，不额外等待目标稳定；合爪首次下发前重新检查当前真实目标、位置、障碍和反馈，失效则保持开度等待。
4. 抓取时底盘停车；相机到位后左爪闭合到 **0°**、右爪到 **5°**，用单调时钟等待 **0.5 秒**。合爪一旦启动，后续目标或相机反馈短暂失效不会自动松爪或重置合爪计时；明确取消、超时或故障仍会结束任务并保持已发布姿态。原地 `grasp` 从本步骤开始，不要求视觉目标、不扫障、不负责接近。
5. 完成后发出相机回正指令，不等待回正反馈；更新记忆，保持夹持并停车，不丢弃。
6. 关闭相机舵机时，按图像位置接近；过近且足够居中时按 **0.1 m/s** 自动倒退，回到目标带即停止倒退。无相机反馈时，进入目标带按宽度张爪一次；原地抓取直接合爪。

长期闭合角度由 actuator 的 `left_claw_close_deg`、`right_claw_close_deg` 配置，临时张爪和扫走不会改写。普通张爪范围仍为 0～90°，扫走及手动夹爪控制下限独立配置为 −30°。下位机须支持有符号的独立左右爪目标角度；仓库不包含下位机固件。

## 五、停止、超时和记忆

- 一次只执行一个普通动作；执行中可用 `stop` 或 Action 取消中断。`stop` 也会使已经接受但尚未执行的旧任务失效，避免停车后旧任务才开始。
- `/robot/emergency_stop`（`std_srvs/srv/Trigger`）独立于普通动作，锁存停车；`/robot/reset_safety` 显式复位后才能提交新动作，复位本身不会恢复旧任务。`/robot/safety` 为保留最新值的字符串状态话题，`ready` 表示未锁存，其余值是故障原因。软件停车保留最后发布到 `serial_tx` 的舵机目标，不能代替硬件断能或舵机实际位置保持。
- `serial:=true` 时自动要求串口健康反馈；读写错误或健康消息超过 0.25 秒未更新时中止任务并锁存停车。健康只说明上位机桥接收发未报错且近期写完一帧，不代表下位机已经执行。设备失联停车仍须 MCU 看门狗。
- `input_timeout` 是 actuator 自身的 TTL 上限，另检查本地单调时钟接收年龄；重复/乱序控制消息不能刷新旧指令寿命。坏控制数值及越界控制速度会锁存停车。
- `align` / 目标型接近 / 扫走的底盘运动指令累计受 `max_tracking_motion_sec` 约束，当前默认 10 秒；暂停等待不计入，超出锁存停车。它不是里程计距离或实测运动时间。
- 目标型抓取默认总超时 **180 秒**，其他动作 **60 秒**，可用 `timeout_sec` 修改。时间到、取消或成功后底盘保持停止，不自动重启。
- Action 反馈显示实际等待阶段：`waiting_for_gripper_angles` 等待有效开度，`waiting_for_opening` 等待下发张爪，`opening` 等待张爪结束，`stale_or_invalid_target` 表示目标失效，`grasp_pitch` 等待相机到位，`claw_close` 才是合爪阶段。临时帧匹配等待不会覆盖同一目标尚未过期的有效开度；张爪前没有有效宽度时不张爪；张爪后保持已保存开度，合爪仍需当前真实目标有效。`waiting_for_open_pitch` 表示等待相机达到张爪角度。
- 取消或超时停止后续步骤，保持最后已发布的夹爪和相机目标角度，不把未发布的新目标夹带到停车帧里。目标消息过期、真实目标丢失时停止目标型抓取的底盘接近；单独 align 允许短时预测对准，但始终不改夹爪开度。
- 移动、转向和扫走使用计时控制，没有里程计完成确认；合爪也没有夹持传感器确认。
- 接近或扫障阶段原目标丢失、但相机反馈仍新鲜时，底盘先按目标最后横向误差以 `search_turn_speed_mps` 低速原地转 `search_turn_sec`，短暂停稳后，相机以 `search_pitch_speed_deg`（默认 20°/秒）先低头到 `cam_max_deg`，再抬头到 `cam_min_deg`，每个任务最多触发 `search_max_attempts`（默认 3）轮寻找原目标，超过上限仍未找到则保持停车和相机角度，反馈 `search_exhausted`。转向和俯仰搜索期间不累计重绑定超时；重新看到真实目标后清零本轮搜索完成标志，后续再次丢失仍可补搜，直到达到总次数上限。反馈过期时停止搜索角度推进。尚未锁定目标、相机关闭或进入合爪流程后不启动搜索。
- 记忆分别记录任务、抓取和扫走。扫走记录正式目标、障碍编号、左右侧及完成/中断状态，不计入抓取次数，不声称已物理清障。
- 抓取记录类别、编号、左右闭合角度及结果；重复完成通知不会重复计数。旧丢弃历史字段仅作兼容保留，新任务不产生丢弃记录。
- 目标型抓取和 `grasp` 的 Action 成功消息明确写 `physical grasp unconfirmed`；当前协议没有夹爪位置、电流或接触反馈，成功只表示合爪计时完成。
- 记忆仅保存在本次节点运行的内存中，重启清空；参数保存在 YAML 中。

## 六、调用示例

启动：

```bash
BP_DEBUG=actuator,alignment ros2 launch block_perception perception.launch.py serial:=true
```

显式抓取 class_2：

```bash
ros2 action send_goal /robot/execute block_interfaces/action/RobotTask "{operation: target_grasp, has_target_class: true, target_class_id: 2}" --feedback
```

自动执行一次指定类别抓取：

```bash
ros2 launch block_perception perception.launch.py serial:=true autonomous:=true target_class:=2
```

取消与查询：

```bash
ros2 service call /robot/execute/_action/cancel_goal action_msgs/srv/CancelGoal '{}'
ros2 action send_goal /robot/execute block_interfaces/action/RobotTask "{operation: stop}"
ros2 service call /robot/emergency_stop std_srvs/srv/Trigger '{}'
ros2 service call /robot/reset_safety std_srvs/srv/Trigger '{}'
ros2 topic echo /robot/memory --once --qos-durability transient_local
ros2 service call /robot/memory/get std_srvs/srv/Trigger '{}'
```

## 七、实现位置

- `nodes.py` / `first_grasp.py`：类别选择、正式目标锁定、障碍几何判断、对准和抓取就绪条件；`first_grasp_task.py` 为兼容可执行入口。
- `sweep.py` / `actuator.py`：扫走计时与指数衰减、单侧内收、视觉张爪、合爪及唯一串口输出。
- `action_api.py` / `RobotTask.action` / `TargetTask.msg`：动作参数验证、显式类别、任务关联、取消和超时。
- `task_memory.py`：任务、扫走及抓取记忆；`perception.yaml`：角度、速度、衰减及等待时间配置。

修改接口后须重建所有依赖包并重启相关节点。参数说明见 [parameters.md](parameters.md)，串口说明见 [serial_protocol.md](serial_protocol.md)。
