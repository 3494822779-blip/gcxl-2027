# 动作行为复查（2026-11-10）

本次先修第一轮已确认的软件保护缺口，再沿完整任务检查动作衔接。没有连接真实串口、相机或驱动机器人；串口集成测试只使用伪终端。

## 本轮已经修正的动作衔接

| 场景 | 原行为 | 当前行为 |
|---|---|---|
| 移动中发 stop | 因忙而拒绝 | 中断当前任务、立即发布零轮速；旧的待执行任务也失效 |
| 需要持续禁止运动 | 没有独立入口 | emergency_stop 锁存；reset_safety 仅解除锁存，不恢复旧任务 |
| 刚指定爪内收就扫走 | 轮子与爪同时开始 | 先停车等待爪内收，再累计扫走时间 |
| 扫完后障碍仍在 | 只能扫一次，后续可能直接接近 | 恢复爪位、等待、用新观测继续扫；同障碍/总次数超限停车 |
| 扫走中障碍编号变化 | 结束时可能记错扫过的障碍 | 启动时固定本轮障碍编号 |
| 扫完用旧图像重发的控制决定再扫 | 控制时间戳代表当前 tick，掩盖旧观测 | 有效控制保留图像观测时间；重新扫要求观测晚于本轮结束 |
| 张爪过程中底盘接近 | 不等待张爪运动完成 | 张爪等待期间底盘停车 |
| 目标型抓取等相机时目标离开 | 后续角度到位仍合爪 | 首次合爪前再核对真实目标、位置、障碍和反馈 |
| 已开始夹持后反馈短暂丢失 | 合爪计时重置，可能长期卡住 | 保持闭合，用单调时钟完成等待；不自动松爪 |
| 只做 align | 可能执行视觉张爪 | 对准不改变爪开度 |
| 同一物块被跟踪器换编号 | 可能重新按宽度张爪 | 沿用原任务保存的开度与等待进度 |
| 停止恰好落在新姿态尚未发布时 | 停车帧可能首次带出新姿态 | 保留最后已经发布到 serial_tx 的姿态 |
| 目标持续有效但始终达不到完成条件 | 可一直运动到任务总超时 | 对准/接近/扫走另有累计运动指令时间预算 |

同时修正了 YAML 中一个实际不一致：`alignment.grasp_pitch=0.7381317007977318` 实为约 42.29°，原注释却写 45°；现在改为 0.7853981633974483 rad，与 actuator 的 45° 一致。没有恢复已取消的“超过抓取角度不许抓”的规则；合理超调仍允许，物理范围错误的反馈另行拒绝。

## 仍需明确的动作策略

以下包含可从代码确认的行为和需要实物验证的风险，未把缺少标定的信息直接写成新机械限制。

### 1. 障碍还够不到，扫走计时就可能开始

位置：`block_perception/first_grasp.py:15`、`actuator.py` 的扫走启动分支。

只要障碍在目标前面且横向相交就可以启动扫走，没有“障碍已经进入爪的可触达区”的门槛。现在虽已等爪内收并限制重试，但仍可能在远处把两次机会用完，实际还没有接触物块。

建议把“发现障碍”“抵达扫走准备位置”“进入接触区”“执行扫走”“复查”分成状态。接触区应按相机姿态和爪覆盖范围标定；准备阶段也要有距离/时间预算。

### 2. 按目标左右选爪，不等于按车身左右选爪

位置：`first_grasp.py:30`。

例如 1280 宽画面中，目标中心 x=1000、障碍中心 x=950，两者都在画面右边；算法因为障碍在目标左边，选择左爪。左爪能否够到它，取决于机构覆盖范围，单靠相对目标中心不能确认。

建议用车体坐标或标定后的左右爪工作区域选爪；两爪都够不到时先调整车体位置。当前横向相交判断也没有覆盖车身、张开爪、转弯和扫出物块的完整占用区域，侧面障碍、墙面及模型没识别的物体不能据此排除。

### 3. 已夹着一个物块，下一次抓取会怎样

位置：`action_api.py` 的任务接收、`actuator.py` 的视觉张爪、`task_memory.py` 的 `held`。

抓取完成会保持夹持，但新目标任务不会要求先明确处置已有夹持物。下一次视觉张爪或扫走可能把上一块放掉、挤出或带着它碰到新目标。记忆记录了夹持指令，却没有用它建立动作准入规则；也没有夹持传感器确认。

建议约定“疑似持物时允许哪些动作”，并要求显式释放/放置或人工确认后才能重新抓。`align` 意外张爪已修，但新 `target_grasp` 仍需这条产品行为规则。

### 4. 停车指令已经发出，不等于车已经停稳

位置：`actuator.py` 的 `begin_grasp()` 和合爪阶段。

目前允许在第一次满足视觉条件后较快发出合爪；底盘的制动、地面打滑和物块滑动没有反馈。尤其较快接近时，发零轮速后仍可能有惯性位移。

建议优先以轮速/里程反馈确认停稳；没有反馈时，设置经实测的停车等待。它与“目标画面要稳定多久”是不同条件。本轮保持原先“不额外等视觉稳定”的约定，没有凭空选定实车制动时间。

### 5. 取消扫走后，爪可能停在 −30°，下一条 move/turn 没有姿态检查

位置：`action_api.py` 的 `hold()`、`move` / `turn` 分支。

保持当前姿态可以避免意外松爪，但爪可能仍抵着障碍，或处于不适合行走的姿态。取消后立即后退、旋转，可能拉扯或刮碰物块。直接要求自动回爪也可能释放夹持物，因此不能只加一个无条件复位。

建议增加显式恢复动作或行走姿态准入，并区分空爪、持物、接触中和未知状态。没有爪实际角度/接触反馈时，系统只能知道下发目标，不能确认恢复成功。

### 6. 自动倒退只看前面的目标，没有后方信息

位置：`nodes.py` 的固定相机 `too_close` 分支；`action_api.py` 的负距离 move。

固定相机模式会为了回到目标带自动后退，普通 move 也允许负距离；两者都没有后方障碍输入。前方目标太近不代表后方有空间。

建议自动任务默认停车求助，或仅在后方感知/可验证的短距离走廊内倒退。手动负距离移动则应明确由调用者保证后方空间；软件不能从当前前置相机推断。

### 7. 一次张爪的宽度估计可能与最终抓取时不同

位置：`gripper.py:9`、`actuator.py` 的 `opening_angles` 保存逻辑。

现在在 22° 低头时取框宽，使用固定 `mm_per_px`，之后继续接近到 45° 才抓取。距离、透视或物块姿态变化会改变像素宽度；跟踪器换编号沿用开度也依赖“确实是同一物块”的几何推断。一次张爪能避免抖动，但不能据此确认最终开度合适。

建议按距离/俯仰标定宽度换算，并在合爪前验证目标仍落在已打开的爪口内。可以只做“开度是否足够”的检查，无需恢复每帧追着框宽调整的行为。

### 8. 靠近时的微小转向可能被最小轮速抬得很大

位置：`actuator.py` 的 `min_turn_speed` 分支。

当前 YAML 的最小转向分量为每侧 0.17 m/s；轮距 0.15 m、最大角速度 2 rad/s 时，合成转向又会被限到对应每侧约 0.15 m/s。即使视觉已经把微小误差的转向增益降低，执行端仍可能把非零转向抬到这个量级；误差换符号时会突然反向。

建议在实车测得静摩擦门槛后，加转向滞回、加速度限制或电机层补偿；近距离是否允许原地转向也应单独约定。不能只看上游 yaw 增益已经变小就认定转向柔和。

### 9. 相机回正、目标恢复和下一任务之间仍有边界

抓取结果不等待相机回正反馈；下一条移动或目标任务可以较快开始。丢失目标后单帧真实观测恢复即可继续，几何重绑定也可能在堆叠的同类物块间接错身份。新任务是否必须等相机稳定、恢复目标是否需要连续观测，以及多物块密集时是否禁止重绑定，都应明确约定。

### 10. 启动时底盘不动，不代表舵机不动

`actuator` 一启动就周期发布爪初始目标和相机目标。重启前若夹爪或相机不在这些位置，仍会发生舵机运动；当前协议没有“暂不改变某个舵机目标”的字段，也没有夹爪实际角度反馈。软件急停保持的是已发布目标，同样不能令正在走向该目标的舵机立即停在当前位置。

建议把初始化姿态作为显式动作，并与下位机约定接管、保持当前位置和断能策略；初始化前是否允许操作者接近夹爪也应说明。仅增加一个上位机布尔开关不能弥补缺少的反馈和协议能力。

### 11. 很小的 move/turn 也可能输出整整一拍

位置：`action_api.py` 的计时移动和 `actuator` 的 0.05 秒控制周期。

任何非零计时运动第一次 tick 都会输出轮速，通常下一次 tick 才检查是否到时。以名义周期估算，0.5 m/s 的一拍约 2.5 cm；当前轮距 0.15 m、每侧转向速度 0.17 m/s 时，一拍原地转向约 6.5°。因此请求 1 mm 或 1° 并不意味着设备只运动那么一点。实际位移还受电机、制动及调度影响，这些数字不是实测精度。

建议拒绝低于当前控制分辨率的请求，或根据剩余时长降低本拍速度并结合里程反馈；仅靠缩小 `distance_m` / `angle_deg` 不足以实现可靠微调。
